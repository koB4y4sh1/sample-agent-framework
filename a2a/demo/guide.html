Code Review Desk A2A Agent

このページは、a2a/demo の A2A デモがどのような仕組みで動いているかを説明するガイドです。 このデモは「A2A で動くコードレビュー受付センター」として、レビュー依頼を task として受け取り、状態更新とストリーミングで結果を返します。

重要な点は、LLM を直接呼び出す部分と、A2A の task lifecycle を管理する部分が分かれていることです。 agent.py は OpenAI SDK 呼び出し、server.py は A2A サーバ、client.py は A2A クライアントを担当します。

全体像

A2A では、クライアントが直接 LLM を呼ぶのではなく、A2A サーバに task を送ります。 サーバは task の状態を管理しながら、必要に応じて LLM を呼び、結果を artifact として返します。

client.py レビュー依頼を Message として送信
A2A JSON-RPC send_message / get_task / cancel_task
server.py Task 状態と artifact を管理
agent.py OpenAI SDK で LLM を呼び出す
OpenAI コードレビュー結果を生成

ファイルの役割

ファイル 役割 初心者向け説明
agent.py OpenAI SDK で LLM を呼ぶ 「レビュー担当者」の頭脳部分です。プロンプトと OpenAI API 呼び出しを持ちます。
server.py A2A サーバを起動する 受付窓口です。依頼を受け、task 状態を更新し、結果を返します。
client.py A2A サーバへ依頼を送る 利用者側の送信ツールです。task 送信、状態取得、キャンセルを試せます。
README.md コマンド例 すぐ動かすための最短手順です。

リクエスト処理の流れ

Agent Card を取得する

client.py は /.well-known/agent-card.json から、エージェント名、スキル、JSON-RPC の接続先を取得します。

task を送信する

send_message でレビュー依頼を送ります。本文は A2A の Message と Part(text=...) に入ります。

TaskStore に task が保存される

InMemoryTaskStore が task の状態を保持します。このため get_task で状態を取得できます。

Executor が状態を更新する

CodeReviewExecutor が submitted、working、completed などの状態を送ります。

OpenAI SDK でレビューする

agent.py の CodeReviewAgent.stream() が Responses API のストリーミングを受け取り、同じ context_id では前回レビューを踏まえた再レビューを行います。

artifact_update で結果を返す

executor.py はまず Review Draft をストリーミングし、その後に Summary、Key Findings、Test Plan、Follow Up の複数 artifact へ整理して返します。

Task の状態

このデモで確認できる task 状態は以下です。

SUBMITTED受付直後
WORKINGレビュー中
COMPLETED正常完了
CANCELEDキャンセル
REJECTED受付拒否
FAILED処理失敗

なぜコードレビュー受付センターなのか

A2A のデモでは、単なるチャットよりも「受付」「処理中」「結果返却」「キャンセル」という流れがある題材の方が分かりやすくなります。 コードレビューは、依頼を task として受け付け、処理中に状態を出し、結果を report として返すため、A2A の仕組みと相性がよい題材です。

起動

.env の AZURE_OPENAI_ENDPOINT を load_dotenv() で読み込み、認証には az login 済みの Azure CLI を使います。

uv run python a2a/demo/server.py --model gpt-4.1-mini --port 41250

VS Code では Demo A2A launch configuration から起動できます。

task 送信とストリーミング

通常のレビュー依頼です。LLM を呼び出し、まず Review Draft を流し、その後に成果物ごとの artifact を表示します。

uv run python a2a/demo/client.py --text "このPRのリスクをレビューして: 認証ミドルウェアを追加し、全APIに適用した"

context 継続

同じ context_id を使うと、前回のレビュー内容を踏まえた再レビューになります。解消済み、未解消、新規懸念が見分けやすくなります。

uv run python a2a/demo/client.py --context-id review-session --text "このPRのリスクをレビューして: 認証ミドルウェアを追加し、全APIに適用した"
uv run python a2a/demo/client.py --context-id review-session --text "指摘を踏まえて認証エラー時のハンドリングを修正しました。再レビューしてください。"

task 状態取得

client.py は送信直後に get_task を呼び、現在の状態を表示します。

uv run python a2a/demo/client.py --text "この変更のテスト観点をレビューしてください: キャッシュ層を追加した"

task キャンセル

通常のレビュー依頼に対しても、クライアント側から cancel_task を送れます。

uv run python a2a/demo/client.py --text "このPRのリスクを詳しくレビューしてください: API ゲートウェイ配下の認証処理を全面的に見直した" --cancel-after 2
通常のレビュー依頼は Azure OpenAI API を呼び出します。 AZURE_OPENAI_ENDPOINT を設定し、事前に az login を実行してください。

前提

  • a2a/demo は agent-framework/demo から import しません。
  • LLM 呼び出しには OpenAI SDK の AsyncOpenAI と Responses API を使います。
  • OPENAI_MODEL 環境変数を設定すると、--model 未指定時の既定モデルを変更できます。
