A2A サンプル 1.10 エラー処理

失敗したときに、分かる形で返す

このサンプルは、入力の不備や処理中の失敗が起きたときに、Task の状態としてどう伝えるかを学ぶページです。正常系だけでなく、異常系を見せることも大切です。

学ぶことrejected / failed / completed
主な登場ファイルagent.py / client.py
ポイント失敗の理由を読みやすくする

1. 何をしているサンプルか

入力チェックで止める場合は rejected、受け付けた後に処理が失敗した場合は failed を返します。成功時の completed と比較して確認します。

agent.py入力に応じて reject / failed / complete を呼び分けます。
client.pystatus_update の state と message を表示します。

2. 用語のイメージ

rejected入力や条件が合わず、処理を受け付けない状態です。
failed受け付けた後、処理中に失敗した状態です。
completed正常に完了した状態です。

3. 全体の流れ

1. リクエストを受け取るまず入力や状況を確認します。
↓
2. 入力や処理条件を確認するreject / fail / ok のどれに当たるかを判断します。
↓
3. Task 状態として返すrejected または failed と理由メッセージを返します。
↓
4. クライアントが表示するユーザーが次の行動を決めやすくなります。
ポイント
入力不備は rejected、処理中の失敗は failed と分けると、client 側で次の対応を判断しやすくなります。

4. サーバー側の見どころ

サーバーは、TaskUpdater を使って Task の状態を明示します。サンプルでは入力が reject なら rejected、fail なら failed になります。

if text == "reject": await updater.reject(message=message) return if text == "fail": await updater.failed(message=message) return

5. クライアント側の見どころ

クライアントは、status_update の state と message を読みます。状態名を見ることで、入力不備なのか処理失敗なのかを分けられます。

if event.HasField("status_update"): status = event.status_update.status print(TaskState.Name(status.state))
エラー処理は、A2A を安心して使うための基本です。rejected と failed を分けると、失敗時の見え方が明確になります。
