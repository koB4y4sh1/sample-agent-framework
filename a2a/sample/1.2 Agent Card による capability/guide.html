A2A サンプル 1.2 Agent Card による capability

Agent Card で「何ができるか」を先に伝える

このサンプルは、サーバーが Agent Card に capability を載せて公開し、クライアントがその内容を読んで接続できることを示します。まず名刺を見てから話し始める、という流れを学ぶページです。

学ぶことcapability / skill / interface
主な登場ファイルagent.py / client.py
ポイントカードを見て接続先を判断

1. 何をしているサンプルか

このサンプルでは、サーバーが自分の機能を Agent Card に書き込みます。クライアントはまずそれを取得して、どのプロトコルで接続するか、どんなスキルがあるかを確認します。

agent.pyAgent Card を作成し、capabilities や interfaces を公開します。
client.pyAgent Card を取得して、内容を表示します。

2. 用語のイメージ

capabilitiesストリーミングやプッシュ通知など、できることの一覧です。
skillsエージェントが得意なタスクや会話テーマです。
supported_interfacesGRPC / JSONRPC / HTTP+JSON などの接続方法です。

3. 全体の流れ

1. サーバー起動Agent Card を用意して公開します。
↓
2. クライアントが Agent Card を取得どの機能があるかを確認します。
↓
3. 接続方法を決める対応する transport を選びます。
↓
4. カード内容を表示名前・説明・skill・interface を画面に出します。
ポイント
この段階ではメッセージ送信はまだしていません。まず「話せる相手か」を判断するのが Agent Card の役割です。

4. サーバー側で見ているもの

サーバーは Agent Card に、自分の名前、説明、サポートするプロトコル、例としての skill を入れます。これでクライアントは利用前に機能を把握できます。

AgentCard( name="Sample Agent", capabilities=AgentCapabilities(streaming=True), skills=[AgentSkill(...)] )

5. クライアント側での見方

クライアントは A2ACardResolver でカードを取得し、display_agent_card で中身を確認します。接続先選択の前に、どんな相手かが分かるのが大事です。

resolver = A2ACardResolver(httpx_client, args.url) card = await resolver.get_agent_card() display_agent_card(card)
Agent Card は、A2A の「自己紹介カード」です。ここを読めると、後続のタスク送信がかなり分かりやすくなります。
