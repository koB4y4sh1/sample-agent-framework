A2A サンプル 1.1 基本的なA2A

初心者向けガイド: 基本の処理の流れを図で理解する

このページは、hello_world_agent.py と client.py が どの順番で動くのかを、できるだけやさしく整理したドキュメントです。 「サーバーが何をしているか」「クライアントが何を送っているか」「タスクがどう進むか」を ひと目で追えるようにしています。
このサンプルは v1.0 基準 で説明しています。

見る対象 1.1 の基本的な A2A 処理
主なファイル hello_world_agent.py / client.py
学べること 送信・受信・タスク更新

1. このサンプルでやっていること

このサンプルは、ユーザーが入力したメッセージを A2A クライアントからサーバーへ送り、 サーバー側のエージェントが内容を見て返答し、その結果をストリームで返す流れを示します。

hello_world_agent.py サーバー側です。エージェントの返答ロジック、タスク管理、各種トランスポートの起動を担当します。
client.py クライアント側です。Agent Card を見つけて接続し、メッセージを送ってストリーム結果を表示します。

2. 使う前提の用語

Agent Card
このエージェントが何に対応しているかをまとめた名刺のような情報です。
Message
ユーザーが送る1通の入力メッセージです。
Task
1回の依頼を表す単位です。進行状況や結果がここに紐づきます。
EventQueue / TaskUpdater
タスクの状態変化や成果物を、順番にクライアントへ伝えるための仕組みです。

3. 全体の流れ

まずクライアントが Agent Card を見つけます。そのあと接続方法を決め、ユーザー入力を送信します。 サーバーはタスクを作成し、作業中メッセージを出し、最後に成果物を返します。

1. クライアント起動 client.py が起動し、接続先 URL とトランスポート候補を準備します。
↓
2. Agent Card を取得 対応プロトコルや公開 URL を確認して、実際の接続先を決めます。
↓
3. メッセージ送信 ユーザー入力を Message に変換して、サーバーへ送ります。
↓
4. サーバーが処理 hello_world_agent.py が内容を見て返答文を作ります。
↓
5. ストリームで返答 status_update や artifact_update を順番に受け取り、画面に表示します。
ポイント
A2A では「1回送って終わり」ではなく、タスクの進行状況 と 最終成果物 を 分けて受け取れるのが大きな特徴です。

4. サーバー側の処理

サーバーは、まず Agent Card を用意して、どのプロトコルで話せるかを公開します。 そのあと、受け取ったメッセージを SampleAgentExecutor が読んで、 入力内容に応じた返答を作ります。

サーバーの役割を図で見る

Agent Card を作る 名前、説明、機能、接続先 URL をまとめます。
↓
Task Store を用意する 今あるタスクを一時的に記録します。
↓
Request Handler に渡す クライアントからのリクエストを実際のエージェント処理へつなぎます。
↓
REST / JSON-RPC / gRPC を公開する 同じ処理を複数の接続方法から利用できるようにします。
if "hello" in ql or "hi" in ql: return "こんにちは。はじめまして。" if "how are you" in ql: return "元気です。お気遣いありがとうございます。" if "goodbye" in ql or "bye" in ql: return "さようなら。すてきな一日をお過ごしください。"

5. クライアント側の処理

クライアントは、まず接続先から Agent Card を読み取ります。 次に、実際に使うトランスポートを決め、ユーザー入力を Message として送ります。 返ってきたイベントはストリームで順に表示します。

クライアントの役割を図で見る

1. URL を受け取る どのエージェントへつなぐかを決めます。
↓
2. Agent Card を取得する そのエージェントの対応機能と接続方法を確認します。
↓
3. メッセージを入力する ターミナルから文字を入力します。
↓
4. SendMessageRequest を送る Message を包んでサーバーへ送信します。
↓
5. ストリームを読む タスク開始、状態更新、成果物更新、最終メッセージを順番に表示します。
ポイント
クライアントは、結果を一気に待つのではなく、途中経過も見せてもらう ことで 「今何が起きているか」をわかりやすくしています。

6. タスクの状態がどう変わるか

タスクは、送ったあとに少しずつ状態が変わります。ここでは、その変化を簡単な流れで示します。

SUBMITTED タスクを受け取った直後です。
↓
WORKING エージェントが処理中です。クライアントには進行中メッセージが届きます。
↓
COMPLETED / FAILED / CANCELED / REJECTED 処理が終わった状態です。クライアントはここで終了扱いにします。

7. 初心者向けの読み方

  • まず client.py を見て、「どこに送るのか」を把握します。
  • 次に hello_world_agent.py を見て、「受け取ったあと何を返すのか」を確認します。
  • 最後に Task と EventQueue を見ると、「途中経過がどう流れるか」がつながります。

8. そのまま試すときの見どころ

  • 入力が hi のとき、あいさつが返るか。
  • 入力が how are you のとき、会話を続ける返答になるか。
  • 入力のあとに タスク開始、タスク状態更新、タスク成果物更新 が順番に出るか。
このドキュメントは、A2A の基本的な処理の流れを最初につかむための入門ページです。
