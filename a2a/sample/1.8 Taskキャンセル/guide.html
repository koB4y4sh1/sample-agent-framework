A2A サンプル 1.8 Taskキャンセル

進行中の Task を途中で止める

このサンプルは、動いている Task をキャンセルして、サーバーやクライアントの状態がどう変わるかを学ぶページです。待ち時間が長い処理を止めたいときに役立ちます。

学ぶことcancel / canceled / 停止
主な登場ファイルagent.py / client.py
ポイント終わる前に止められる

1. 何をしているサンプルか

クライアントが Task を送ったあと、必要に応じてキャンセル要求を送ります。サーバーは処理を止められるなら止めて、状態を canceled に変えます。

agent.pyキャンセル要求を受けて、実行中の処理を止めます。
client.py途中で中断したいときに cancel を送ります。

2. 用語のイメージ

CancelTaskRequest「この Task はもう止めてください」という依頼です。
canceledキャンセル済みであることを示す状態です。
graceful stop途中状態を壊さず、自然に止める考え方です。

3. 全体の流れ

1. Task を開始するまずは処理を走らせます。
↓
2. 途中で止めたくなるユーザーが中断したいと判断します。
↓
3. cancel を送るクライアントがキャンセル要求を出します。
↓
4. サーバーが停止処理を行う実行中のループや待機を止めます。
↓
5. canceled を返す止まったことを明示します。
ポイント
キャンセルは「失敗」ではなく、「もう続けない」という正常な操作です。長い処理ほど重要になります。

4. サーバー側の見どころ

サーバーは、実行中の task_id を記録しておきます。キャンセル要求が来たら実行中リストから外し、ループ側はそれを見て途中終了します。

if task_id not in self.running_task_ids: return await TaskUpdater(event_queue, task_id, context_id).cancel()

5. クライアント側の見どころ

クライアントは、最初の Task イベントから task_id を取り出し、その id を指定してキャンセルします。結果よりも、停止の流れを理解するのが大切です。

canceled_task = await client.cancel_task( CancelTaskRequest(id=task_id) ) print(TaskState.Name(canceled_task.status.state))
Taskキャンセルは、ユーザーの操作を尊重するための大切な仕組みです。長い処理にこそ効きます。
