A2A サンプル 1.7 Task状態取得

送信した Task の今の状態をあとから確認する

このサンプルは、いちど送った Task の状態を読み直して、いま submitted なのか、working なのか、completed なのかを確認する流れです。長くかかる処理の途中確認に向いています。

学ぶことtask_id / status / 再確認
主な登場ファイルagent.py / client.py
ポイント状態を読むだけでも役立つ

1. 何をしているサンプルか

クライアントは最初に Task を送信し、そのあと task_id を使って状態を問い合わせます。サーバーは今の状態を返すだけなので、処理の進み具合を確認しやすくなります。

agent.pyTask を保存し、状態問い合わせに応答します。
client.pytask_id を持っておき、必要なタイミングで再確認します。

2. 用語のイメージ

task_idあとから同じ Task を探すための番号です。
statusSUBMITTED / WORKING / COMPLETED などの Task 状態です。
GetTaskRequesttask_id を指定して、いまどうなっているかを問い合わせるリクエストです。

3. 全体の流れ

1. Task を送るまずは処理を開始します。
↓
2. task_id を受け取るあとから探すための鍵になります。
↓
3. 状態を問い合わせる一定時間ごとに現在の様子を確認します。
↓
4. サーバーが現在の状態を返すSUBMITTED / WORKING / COMPLETED などが見えます。
ポイント
「送ったあとにどうなったか」を見たいときは、メッセージを送り直すより状態問い合わせが分かりやすいです。

4. サーバー側の見どころ

サーバー側では InMemoryTaskStore が Task の現在状態を保持します。サンプルコードでは、状態を変えるたびに TaskUpdater が store へ反映します。

request_handler = DefaultRequestHandler( agent_executor=GetTaskAgentExecutor(), task_store=InMemoryTaskStore(), agent_card=agent_card, )

5. クライアント側の見どころ

クライアントは task_id を覚えておき、必要なときに GetTaskRequest で状態を見に行きます。長い処理でも、今の段階を把握しやすくなります。

task = await client.get_task(GetTaskRequest(id=task_id)) print(TaskState.Name(task.status.state))
Task状態取得は、A2A の「あとから見に行ける」性質を理解するための入り口です。進捗確認や監視に役立ちます。
