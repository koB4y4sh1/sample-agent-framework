A2A サンプル 1.3 Task送信

ユーザーの入力を Task として送る

このサンプルは、クライアントがメッセージを送ると、サーバー側で Task が作られて処理される流れを学ぶものです。A2A では「会話」だけでなく「タスク」という単位で依頼を扱います。

学ぶことSendMessageRequest / Task
主な登場ファイルagent.py / client.py
ポイント送信後に状態更新が流れる

1. 何をしているサンプルか

クライアントがテキストを入力し、それを `Message` に包んで `SendMessageRequest` として送ります。サーバーはそれを受け、タスクを作成し、イベントを返します。

client.pyMessage を作って送信し、返ってくるイベントを読む。
agent.pyTask を作り、処理結果を返す。

2. 用語のイメージ

SendMessageRequestメッセージ送信用のリクエストです。
Task1回の依頼を表す箱です。
artifact最終的な返答や成果物です。

3. 全体の流れ

1. ユーザーが入力ターミナルで文章を入力します。
↓
2. Message を作る入力文を A2A の Message に変換します。
↓
3. SendMessageRequest を送るクライアントがサーバーへ依頼を送信します。
↓
4. サーバーが Task を生成受け取った依頼をタスクとして管理します。
↓
5. イベントを返すstatus_update や artifact を順番に返します。
ポイント
Task 送信のサンプルでは、「送る → 受ける → 状態が変わる」が一連の流れとして見えます。

4. クライアント側の見どころ

client.py は `SendMessageRequest(message=message)` を作り、ストリームを `await` で読みます。つまり送信と受信が分かれています。

message = Message(...) request = SendMessageRequest(message=message) stream = client.send_message(request)

5. サーバー側の見どころ

agent.py はユーザー入力から返答を組み立て、Task を生成してから artifact を返します。依頼の単位が明確なので、後で進行状況も扱いやすくなります。

Task(id=task_id, ...) await updater.add_artifact(...) await updater.complete()
Task 送信は、A2A で「1回の依頼」をどう表現するかをつかむ入口です。次の同期応答・ストリーミングの理解にもつながります。
