⑥ 設定と実行

設定は HA_、実行は uv run python -m harness.main

このページでは、どこに何を書いて、どう起動し、どのファイルを見ればよいかをまとめます。

設定が読み込まれる流れ

図 5-1 ｜ .env から Agent へ

.envHA_ 変数を書く
→
settings.pyHA_ を読み取る
→
main.pyCLI 引数と合成
→
agent.pyAgent に反映

環境変数

HA_FOUNDRY_PROJECT_ENDPOINT=https://...
HA_FOUNDRY_MODEL=gpt-5.4-nano
HA_TOOLBOX_NAME=playwright-browser
HA_TOOLBOX_VERSION=2
HA_TOOLBOX_API_VERSION=v1
HA_GOAL_FILE=agent-framework/harness/goal.md

settings.py が HA_ で始まる環境変数を読みます。 .env に書いておけば、コード側で load_dotenv() しなくても読み込まれます。

goal.md の役目

図 5-2 ｜ goal.md は CLI 引数ではなく instructions に入る

goal.md目的・ログイン情報
→
agent.pyinstructions に追加
→
Agent作業文脈として読む

goal.md は CLI 引数には変換しません。Agent の instructions に追加されます。 資格情報をログや最終回答に出さない指示も一緒に入れています。

基本実行

uv run python -m harness.main `
  --allowed-domain app.levela.co.jp `
  --session-id example-run-001 `
  --max-cycles 30 `
  --cycle-timeout-seconds 900 `
  --retry-attempts 3 `
  --consecutive-error-limit 3 `
  "app.levela.co.jp を対象に、許可された範囲で作業してください"

長時間実行

uv run python -m harness.main `
  --allowed-domain app.levela.co.jp `
  --session-id overnight-001 `
  --unattended `
  --max-runtime-hours 8 `
  --max-cycles 300 `
  --cycle-timeout-seconds 1200 `
  --retry-attempts 5 `
  --consecutive-error-limit 10 `
  --stall-limit 10 `
  "app.levela.co.jp を対象に、許可された範囲で作業を継続してください"

生成されるファイル

図 5-3 ｜ runs/ 配下に書き出される

runs/
├─ <session-id>.jsonl            ← まずここを見る（実行ログ）
├─ <session-id>.checkpoint.json  ← 再開用の最新状態
├─ <session-id>.heartbeat.json   ← 外部監視用の現在状態
└─ history/
   └─ <session-id>.jsonl         ← Agent の会話履歴（詳細）
ファイル意味優先度
runs/<session-id>.jsonl実行ログ。まずここを見る。最初
runs/<session-id>.checkpoint.json再開用の最新状態。次
runs/<session-id>.heartbeat.json外部監視用の現在状態。監視
runs/history/<session-id>.jsonlAgent Framework の会話履歴。詳細

作業ディレクトリに注意

C:\Workspace\sample_agent_framework で実行してください。 agent-framework ディレクトリ内で実行すると、相対パスの都合で agent-framework/agent-framework/harness/runs のように二重になります。
