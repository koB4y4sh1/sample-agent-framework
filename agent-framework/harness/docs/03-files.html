役割を 4 グループで把握する

図 2-1 ｜ 入口・頭脳・ループ・入出力

入口entry
main.py・settings.py
引数と環境変数を読み、設定を組み立てる。
頭脳agent
agent.py・browser_tools.py
Agent と、ブラウザを動かすツールを定義する。
ループloop
run.py・runtime.py
サイクルを回し、再試行・停止条件を管理する。
入出力io
goal.md・runs/
目的を受け取り、結果ログを書き出す。

役割表

ファイル 一言でいうと 見る場面
main.pyコマンド入口CLI 引数、--allowed-domain、--max-cycles などを確認する時
settings.py環境変数の読み取りHA_ で始まる設定を確認する時
agent.pyAgent を組み立てるLLM・instructions・Toolbox・browser tools の接続を見る時
browser_tools.pyブラウザを実際に動かすCDP 接続・クリック・入力・スナップショットを見る時
run.py長時間ループ本体再試行・サイクル実行・停止条件を見る時
runtime.pyループ用の部品置き場プロンプト・ログ・チェックポイント・結果パースを見る時
goal.mdユーザーの目的とログイン情報Agent に何を目標として渡すか確認する時
runs/実行結果置き場何が起きたか・どこで止まったか調べる時

呼び出し関係（コールグラフ）

図 2-2 ｜ 誰が誰を呼ぶか

main.py設定を作る
→
run.pyループ開始
→
agent.pyAgent 生成
→
browser_tools.py操作実行
設定 制御・実行 判断 ※ run.py は毎サイクル runtime.py の部品（プロンプト・ログ・パース）を使う

起動時の処理順

図 2-3 ｜ 上から順に実行される

1
main.pyコマンド引数と環境変数から設定を作る。
2
run.pyループの準備をして、1 サイクル目を始める。
3
agent.pyFoundryChatClient・Toolbox・browser_* ツール・Harness Agent を作る。
4
runtime.pyAgent に渡すサイクル用プロンプトを作る。
5
browser_tools.pyAgent から呼ばれたらブラウザを操作する。
6
runs/結果を JSONL・checkpoint・heartbeat に保存する。

注意

runs/ はコードではありません。実行すると増える作業記録です。 --resume しないなら削除しても動作には影響しません。
