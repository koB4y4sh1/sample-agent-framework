① 全体像

これは「長時間ブラウザ作業を回すための箱」です

Harness はブラウザそのものではありません。Agent を何度も起動し、失敗したら再試行し、ログを残し、 止めるべき時に止める——その外側の仕組みです。

一番大きな図

図 1-1 ｜ 起動から操作までの最短経路

main.pyCLI 引数を読む
→
run.pyサイクルを回す
→
agent.pyAgent とツールを作る
→
browser_tools.pyブラウザを操作する
→
Azure Browser実際の画面

かなり単純化すると、上の順番で動きます。ユーザーがコマンドを打つと main.py が受け取り、 run.py がループを開始します。その中で agent.py が Agent を作り、Agent が必要に応じて browser_tools.py の browser_goto や browser_click を呼びます。

Harness の責務範囲

Harness が「やる」こと

✅ 作業を短い単位（1 サイクル）に区切る

✅ 失敗したら再試行する

✅ 進捗をログ（JSONL）に残す

✅ 止めるべき状態を判定して停止する

Harness が「やらない」こと

🚫 自分でブラウザをクリックしない

🚫 自分でページを読まない

🚫 権限の無い Azure Workspace を突破しない

🚫 CAPTCHA や MFA を突破しない

1 サイクルの中で何が起きているか

図 1-3 ｜ 「考える人」と「動かす手」は分かれている

1
Harness が指示を渡す「今のページから 1 手だけ進めて」とプロンプトを作る。
2
Agent が考えるLLM が状況を読み、browser_click など呼ぶツールを 1 つ決める。
3
ツールが動かすPython Playwright が Azure 上のブラウザを実際に操作する。
4
結果を記録して次へ状態を JSONL / checkpoint に保存し、続行か停止かを判定する。

重要な前提

playwright-browser Toolbox は、今の構成では主に「リモートブラウザセッションを作る」役目です。 実際のクリックや入力は、今回追加した Python Playwright の browser_* ツールが担当します。 この分担は ④ ブラウザ操作の仕組み で詳しく扱います。
