② Agent Framework と HarnessAgent

「次の一手を考える脳」は Agent Framework が提供しています

この Harness の頭脳は、自前のループではなく Microsoft Agent Framework の create_harness_agent() で作る HarnessAgent です。 ツール呼び出し・履歴・Todo・モード・品質チェックまで、エージェントに必要な部品が最初から束ねられています。

一文でいうと

HarnessAgent = ChatClient（LLM）＋ 指示文 ＋ ツール ＋ プロバイダ群 ＋ ミドルウェア を 1 つにまとめた「自分でツールを呼んで考え続けるエージェント」です。 Harness（run.py）は、この HarnessAgent を毎サイクル 1 回ずつ呼び出すだけです。

HarnessAgent の構成部品

図 2-1 ｜ create_harness_agent() に渡しているもの（agent.py）

ChatClientclient=
FoundryChatClient。LLM 本体との通信。モデル名・プロジェクト・認証を持つ。
指示文agent_instructions=
BASE ＋ 許可ドメイン ＋ unattended ＋ ブラウザツールの使い方 ＋ goal.md を結合。
ツールtools=
browser_start / browser_goto / browser_click … 関数ツール群（＝手足）。
プロバイダ*_provider=
履歴・Todo・モードを“外付け能力”として注入する（次節）。
ミドルウェアmiddleware=
任意。AgentLoopMiddleware.with_judge(...) で応答品質を自己採点させる。

さらに disable_web_search / disable_tool_auto_approval / max_context_window_tokens / max_output_tokens で挙動を絞り込みます。

実際の生成コード（要約）

from agent_framework import (
    AgentLoopMiddleware, AgentModeProvider, FileHistoryProvider,
    TodoProvider, TodoSessionStore, create_harness_agent,
)
from agent_framework.foundry import FoundryChatClient

client = FoundryChatClient(project_endpoint=..., model=..., credential=...)

agent = create_harness_agent(
    client=client,
    name="browser-harness-agent",
    agent_instructions=BASE + DOMAINS + UNATTENDED + BROWSER_USAGE + GOAL,
    tools=browser_function_tools,            # browser_* ツール
    history_provider=FileHistoryProvider(history_dir),   # 会話履歴を保存
    todo_provider=TodoProvider(store=TodoSessionStore()),# 残タスク管理
    mode_provider=AgentModeProvider(default_mode="execute"),
    disable_web_search=True,                 # 勝手な Web 検索を禁止
    disable_tool_auto_approval=True,         # 高頻度ツールは承認なし
    max_context_window_tokens=..., max_output_tokens=...,
    middleware=[AgentLoopMiddleware.with_judge(client, criteria=[...])],
)

プロバイダ＝“外付けの能力”

HarnessAgent の強みは、エージェントに必要な周辺機能を プロバイダとして差し込める点です。 自分でループやメモリを書かなくても、宣言するだけで有効になります。

部品クラス役割
履歴FileHistoryProvider会話履歴をファイルに保存。プロセス再起動後の --resume 材料になる。
TodoTodoProvider / TodoSessionStore長い作業の「残タスク」をエージェント自身に計画・追跡させる。
モードAgentModeProviderplan / execute を切り替える。本サンプルは最初から execute。
判定AgentLoopMiddleware.with_judge応答が基準を満たすかをモデル自身に再採点させる（任意）。

いちばん大事な点：ループは「二重」になっている

ここを誤解すると全体が分からなくなります。ループは 2 つあり、内側は Agent Framework の仕事、 外側が Harness（run.py）の仕事です。

図 2-2 ｜ 外側の Harness ループ × 内側のエージェントループ

外側run.py
サイクルごとに agent.run() を 1 回呼ぶ。再試行・チェックポイント・停止条件を管理（＝⑤ 長時間ループ）。
agent.run() 開始1 サイクル＝1 回
→
LLM が考えるどのツールを呼ぶか
→
ツール実行browser_click 等
→
結果を LLM へ戻す観測を追加
↺
最終応答LOOP_STATUS 付き
内側ループ（Agent Framework が自動で回す） ↺ ツールが必要な間は LLM ↔ ツールを繰り返す

内側ループ（フレームワーク担当）

agent.run() の中で自動に回る。LLM がツールを呼び、結果を読み、また考える——を「最終応答」が出るまで繰り返す。

外側ループ（Harness 担当）

run.py が agent.run() をサイクルとして何度も呼ぶ。長時間化・再開・停止判定はこちら。

呼び出し方：セッションと run

図 2-3 ｜ run.py から HarnessAgent を動かす最小手順

1
build_harness_agent(config)create_harness_agent() で HarnessAgent を組み立てる。
2
agent.create_session(session_id=…)会話の連続性を持つセッション（スレッド）を 1 本作る。
3
await agent.run(prompt, session=session)サイクル用プロンプトを渡して 1 回実行。内側ループが回り、最終応答が返る。
4
LOOP_STATUS を解析応答テキストから CONTINUE / COMPLETE / NEEDS_USER / BLOCKED を読み取り、次サイクルへ。
# run.py（要約）
runtime = await build_harness_agent(agent_config)
agent   = runtime.agent
session = agent.create_session(session_id=loop_config.session_id)

この構成での約束ごと

Agent には tool_search / call_tool を直接使わせず、browser_* ツールだけを見せます。 また disable_web_search=True で勝手な Web 検索を止め、ブラウザ操作は高頻度なので disable_tool_auto_approval=True にしています。送信・削除などの“意味のある承認”は、 指示文側で LOOP_STATUS: NEEDS_USER に止める設計です（詳細は ④ ブラウザ操作）。
