④ ブラウザ操作の仕組み

Toolbox でブラウザを作り、Playwright で操作します

ここが一番つまずきやすい部分です。Toolbox はクリックしません。Toolbox は CDP URL を返します。 その URL に Python Playwright が接続して、クリックや入力をします。

境界線：どこまでが Toolbox で、どこからが Playwright か

図 3-2 ｜ CDP URL が「受け渡しポイント」

1
Agent → browser_start「ブラウザを用意して」と 1 つの道具を呼ぶだけ。
2
Toolbox → Azurecreate_session がリモートブラウザを起動する。
3
Azure → CDP URLwss://… の接続先が返ってくる。ここが境界
4
Playwright → connectconnect_over_cdp(url) でその URL に接続する。
5
Playwright → 操作page.goto / click / fill で実際にページを動かす。

2 つの役目を分けて見る

Toolbox の役目

playwright-browser Toolbox は Azure Playwright Workspace 上にリモートブラウザを作ります。

tool_search("browser")
call_tool(
  "browser_automation___create_session"
)
# → CDP URL (wss://...) を返す

Python Playwright の役目

Toolbox から返った CDP URL に接続して、ページを操作します。

chromium.connect_over_cdp(cdp_url)
page.goto(url)
page.locator(selector).click()

Agent に見せるツール

Agent には tool_search や call_tool を直接使わせません。代わりに次の分かりやすい道具だけを見せます。

ツール意味種別
browser_startブラウザセッションを開始する。準備
browser_goto許可ドメイン内の URL へ移動する。移動
browser_snapshotページのテキスト・リンク・ボタン・入力欄を読む。読取
browser_click指定した selector をクリックする。操作
browser_fill入力欄に文字を入れる。操作
browser_pressEnter や Tab などのキーを押す。操作

なぜ playwright-cli ではなく Python Playwright か

playwright-cli は手元で試すには便利です。ただし Harness に組み込む場合は、外部 CLI プロセスの状態管理が必要になります。 今回は Python の中で接続・操作・close・エラー処理をまとめるため、playwright ライブラリを直接使っています。

HTTP 403 が出る場合

browser_automation___create_session で HTTP 403 が出る場合、コードより先に Azure Playwright Workspace 側の権限を疑います。CDP URL が作れないので、Playwright 接続まで進めません。 詳しい復旧手順は ⑦ エラーの読み方 を参照してください。
